# v1.1 Backlog Candidates

*(DOCUMENT ONLY, DO NOT CODE)*

## Portfolio Comparison
- **User value**: Allows users to compare their portfolio's risk/return profile against standard benchmarks or alternative custom portfolios.
- **Complexity**: High. Requires managing multiple portfolio states and complex comparative UI.
- **Data requirements**: Additional API calls for benchmark tickers.
- **Privacy implications**: None beyond existing portfolio data.
- **Pro/free candidate**: Pro.
- **Why not v1.0**: Out of scope for MVP timeline; focus was on single portfolio analysis.

## Risk Contribution
- **User value**: Breaks down total portfolio volatility to show exactly which assets are contributing the most risk.
- **Complexity**: Medium. Requires more advanced matrix math (covariance matrices) on the frontend or backend.
- **Data requirements**: Historical data for all assets to compute correlations.
- **Privacy implications**: None.
- **Pro/free candidate**: Pro.
- **Why not v1.0**: Math complexity and performance considerations for mobile devices.

## VaR / CVaR
- **User value**: Provides concrete "worst-case scenario" loss estimates (Value at Risk / Conditional Value at Risk).
- **Complexity**: High. Requires sorting historical returns or Monte Carlo simulations.
- **Data requirements**: Deep historical data (at least 1-3 years of daily returns).
- **Privacy implications**: None.
- **Pro/free candidate**: Pro.
- **Why not v1.0**: API rate limits and data payload size for fetching deep history for multiple assets.

## Behavioral History
- **User value**: Tracks how a user's behavioral assessment scores change over time.
- **Complexity**: Medium. Requires storing historical assessment results and building trend graphs.
- **Data requirements**: Historical assessment records in Firestore.
- **Privacy implications**: Increased retention of psychological heuristic data over time.
- **Pro/free candidate**: Free (basic history) / Pro (detailed trend analysis).
- **Why not v1.0**: Focus was on point-in-time assessment to establish the core feature.

## Benchmark Selection
- **User value**: Lets users choose their risk benchmark (e.g., SPY, QQQ, AGG) instead of a hardcoded default.
- **Complexity**: Low. UI update and state management for selected benchmark.
- **Data requirements**: Standard price data for the selected ETF.
- **Privacy implications**: None.
- **Pro/free candidate**: Free.
- **Why not v1.0**: Kept MVP simple with a single assumed benchmark for Beta calculations.

## Concentration Metrics
- **User value**: Flags if a portfolio is overly concentrated in a single asset or sector.
- **Complexity**: Low to Medium. Easy for single assets, harder for sector analysis (requires sector classification data).
- **Data requirements**: Sector metadata from the financial API.
- **Privacy implications**: None.
- **Pro/free candidate**: Free.
- **Why not v1.0**: Prioritized pure volatility/risk metrics over asset allocation analysis.
